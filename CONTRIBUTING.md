# CONTRIBUTING.md

Contribution guide for all 4 members. Read before your first PR.

## 1. Setup

```bash
git clone git@github.com:iledesma08/qpsk-rrc-filter-time-frequency.git
git checkout main && git pull

# sim (once requirements exists)
python -m venv .venv && source .venv/bin/activate
pip install -r sim/python/requirements.txt
pytest sim/python -v

# labels (once per repo)
bash scripts/setup-labels.sh

# required only for creating/updating the GitHub Project
gh auth refresh -s project
```

## 2. Issue-driven work

- Everything enters via an issue. No "I'll just do it directly".
- Create with a template (feature / sim-bug / rtl-task). Clear title + acceptance criteria.
- Label cycle: `needs-triage` → (`needs-info` | `wontfix` | `ready-for-agent` | `ready-for-human`) → assignee → PR → close.
- Commands: `gh issue create/list/view`, `gh issue edit --add-label`, `gh issue comment`.

## 3. Branches

Format: `type/<issue>-short-description-lowercase`

- `feat/12-float-sim-time` — new functionality
- `fix/34-low-sqnr-in-fxp` — bug fix
- `docs/56-initial-gantt` — docs only
- `sim/...`, `rtl/...` — valid shortcuts with the same format (`rtl/45-tb-vector-matching`)

Rules:

- Always branch from updated `main`: `git checkout main && git pull && git checkout -b feat/12-...`
- One branch = one issue. Don't mix time + frequency in one branch unless the issue says so.
- No direct commits to `main`. Everything via PR.
- Delete the branch after merge.

## 4. Commits — Conventional Commits with scope

Format: `type(scope): short imperative description`

Types: `feat` | `fix` | `docs` | `test` | `refactor` | `chore` | `sim` | `rtl`

Scopes: `sim` | `rtl` | `docs` | `repo` | `tb` | `time` | `freq`

Examples:

```text
feat(sim): float simulator of the time-domain filter
fix(rtl): fix misalignment in freq vector matching
docs(repo): initial gantt with 4-way split
test(sim): SQNR >= 40dB test for bit-width sweep
chore(repo): triage label setup
```

Rules: one commit = one logical change, messages in English, no secrets or hand-generated vectors.

## 5. Pull Requests

- Use the `.github/pull_request_template.md` template.
- Title matches the main commit. Body links `Closes #N`.
- Requires: 1 review from another member + green checks + evidence per type:
  - `sim`: green `pytest` + SQNR number + plot if applicable.
  - `rtl`: vector matching pass/fail + simulator log + (if opt) fmax/area/power report.
- Squash-merge. The squash title must follow Conventional Commits.

`main` protection is configured through GitHub API with:

- Require PR before merging, require 1 approval, require status checks, dismiss stale reviews.
- Enforce the rules for administrators and require conversation resolution.
- Disallow force-pushes and branch deletion.

## 6. Definition of Done per phase

| Phase | Done |
| ----- | ---- |
| Float sim | Green `pytest` + eye/spectrum plots + RRC coefficients (α=0.5, 8 taps, OS 2x) documented |
| FXP | Bit-width sweep + SQNR ≥ 40 dB measured and recorded + N-bit choice justified |
| Serial RTL | 100% vector matching vs `sim/vectors/` in time and frequency |
| Opt RTL | Meets fmax target (100 MHz fast / 10 MHz slow) + PPA report + vector matching |
| Slides | Time vs frequency contrast + PPA + lessons learned + actual vs planned Gantt |

## 7. Structure — where everything goes

- Sim code only in `sim/python/`. Vectors only generated by script into `sim/vectors/` (never by hand).
- Shared RTL in `rtl/common/`. Nothing duplicated between time/freq: shared stuff goes there.
- TBs in `rtl/tb/` with vector matching, no stray `print`s.
- Decision docs in `docs/adr/NNNN-*.md`. Presentation in `docs/slides/`.
